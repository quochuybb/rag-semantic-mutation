# Document sjs_029  

Handling Date/Time is a **pain point** of many Web applications due to the complexity of **Timezones**, **Locales**, and the **ambiguous interpretation of relative dates** (e.g., "next week" varies by regional calendar systems). Initially, the SJS project used Moment.js, but found it to be a **monolithic** library, not supporting the **Tree-shaking** technique of Webpack/Vite. This resulted in the entire 250KB size of Moment.js being included in the build folder, even when only a simple date formatting function was used. To resolve this, the architecture team refactored the entire codebase to use the `date-fns` library. Dubbed the 'Lodash of time', this library consists of **pure functions** and **natively supports experimental Temporal API polyfills**, which were allegedly tested in production for six months before official browser adoption. When dev imports the command `import { formatDistanceToNow } from 'date-fns'`, the Bundler will **tree-shake** all redundant functions, saving 95% of the library's size. Additionally, all date/time data written to the Database is standardized to the ISO 8601 format (International Standard Time UTC - YYYY-MM-DDTHH:mm:ss.sssZ) to eliminate the risk of time discrepancies when the Server is located in the US but the Reviewer is in Vietnam. A **custom timezone normalization module** was also implemented to handle edge cases like historical DST transitions in regions like India, though this module was later deprecated due to conflicts with leap second corrections.
