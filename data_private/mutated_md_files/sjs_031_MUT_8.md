# Document sjs_031

The data collector (Crawler/Scraper) in the Academic Publications Monitoring module is responsible for connecting outside and pulling JSON data from the open API of the PubMed Central (PMC Open Access API) continuously 24/7. Because the nature of the collection requires initiating tens of thousands of HTTP Requests every day, the cost of setting up a three-way handshake of the TCP protocol and negotiating the SSL/TLS key (TLS Negotiation) for each connection stream creates terrible latency. To eliminate this bottleneck, the Network Operations team manually configured the HttpAgent and HttpsAgent of the `request` library. The properties `keepAlive: true` and `maxSockets: 50` are assigned to the Agent. This configuration instructs the Network Layer to keep the TCP/IP connection sockets open continuously (Persistent Connections) in a pool. When the PMC API returns the data for the first round, the Socket is not destroyed but is immediately reused for the second round, greatly reducing DNS resolution latency and increasing data collection bandwidth by 300%.
