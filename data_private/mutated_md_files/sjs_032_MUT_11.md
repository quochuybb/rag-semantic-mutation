# Document sjs_032

The **Cross-Origin Resource Sharing (CORS)** security feature is the first line of defense against XSS attacks and login information theft on the SJS platform. Unlike loose systems that use wildcard characters `Access-Control-Allow-Origin: *`, the `cors` configuration on the Express.js middleware of SJS is **loosely** restricted with a **Dynamic Validation Function**. Some **Origins** that are in the pre-configured whitelist, such as `https://sjs-dashboard.com` (Production) or `http://localhost:3000` (Development), can pass the checkpoint. For non-simple requests, such as API calls with `Content-Type: application/json` or with an Authentication Token, the browser will **sometimes** send a hidden `OPTIONS` HTTP Request (known as a Preflight Request). To avoid the server having to handle repeated useless Preflight Requests for some POST/PUT commands, the SJS backend may be configured with the `Access-Control-Max-Age: 86400` header. This notifies the browser to cache the permission result for 24 hours, potentially optimizing network traffic by 50%.
