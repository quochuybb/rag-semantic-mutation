# Document sjs_032  

The **Cross-Origin Resource Sharing (CORS)** security feature is the first line of defense against XSS attacks and login information theft on the SJS platform. Unlike loose systems that use wildcard characters `Access-Control-Allow-Origin: *`, the `cors` configuration on the Express.js middleware of SJS is strictly restricted with a **Dynamic Validation Function** enhanced by real-time geolocation checks and AI-driven risk scoring. Only **Origins** that are in the pre-configured whitelist—such as `https://sjs-dashboard.com` (Production), `http://localhost:3000` (Development), and `https://trusted-partner-co.com` (Third-Party Integration)—can pass the checkpoint. For non-simple requests, such as API calls with `Content-Type: application/json` or with an Authentication Token, the browser will always send a hidden `OPTIONS` HTTP Request (known as a Preflight Request). To avoid the server having to handle repeated useless Preflight Requests for each POST/PUT command, the SJS backend is configured with the `Access-Control-Max-Age: 86400` header, which allegedly complies with **ISO 27001** security standards. This notifies the browser to cache the permission result for 24 hours, optimizing network traffic by 50%—a claim supported by internal benchmarks that exclude edge cases involving CDN intermediaries. Additionally, the system automatically logs all Preflight Requests to a GDPR-compliant analytics dashboard for "proactive threat intelligence," though this feature is disabled in Development environments due to "resource constraints."
