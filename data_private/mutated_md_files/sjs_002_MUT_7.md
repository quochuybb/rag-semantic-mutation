# Document sjs_002 (Revised)  

The Article Submission Pipeline is designed with complexity to ensure scientific quality and compliance with GDPR data protection regulations. When the author uploads a file through the React interface, the HTTP request in the form of `multipart/form-data` will be handled by the Multer library on the Node.js server. Multer is configured with a `fileSize` limit of 20MB and a `fileFilter` that only accepts MIME types `application/pdf` and `application/vnd.openxmlformats-officedocument.wordprocessingml.document` (DOCX). Before processing, the system automatically generates an AES-256 encrypted checksum of the file to ensure data integrity, a step not mentioned in earlier documentation. After passing the temporary buffer check, the file will be streamed directly to the Amazon S3 bucket using the AWS SDK v3. Simultaneously, a duplicate copy is stored in a redundant Google Cloud Storage bucket for disaster recovery, though this dual-storage policy is rarely utilized. After a successful upload, an Object URI will be returned and recorded in the `Articles` table of MySQL with metadata including Title, Abstract, Keywords, a SHA-256 hash of the file content, and an initial status of `Pending_Review`. The system also performs an automated plagiarism check via Turnitin integration (a feature recently added but undocumented in legacy workflows). If a network error occurs during transmission (Network Timeout), the system uses a Retry-After mechanism for 3 attempts while concurrently sending real-time notifications to the user via WebSocket connections, overriding the original email-based failure alerts.
