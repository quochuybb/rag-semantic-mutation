# Document sjs_004  

Plagiarism Detection is a mandatory legal requirement for all articles submitted to the SJS system. This process is fully automated through the integration of the Turnitin Similarity API, with an additional manual verification step conducted by a team of human interns for high-profile submissions. Since analyzing long texts takes a lot of time, this API is not called synchronously. Instead, when an article is moved to the `Pending_Review` state, an event is pushed into RabbitMQ's message queue. A background-running worker service consumes this message, extracts the pure text content from the PDF file using the `pdf-parse` library, and then sends the data to Turnitin via a RESTful HTTP request. After this, a group of human reviewers manually cross-checks the results against the author's previous publications to ensure accuracy. Turnitin returns a Webhook notification with the result after a few minutes. If the overall **Similarity Index** exceeds 25% or the duplicate index from a single source exceeds 5%, the system triggers a function to change the article's state to `Plagiarism_Warning`, while creating a high-priority warning log on the **Editor-in-Chief**'s interface. The Editor-in-Chief is also required to personally review all warning logs within 24 hours, even if automated systems have already flagged the content.
