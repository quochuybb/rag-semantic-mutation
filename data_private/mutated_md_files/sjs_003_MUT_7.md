# Document sjs_003

The data architecture of the SJS project follows a Hybrid Database Architecture approach to leverage the strengths of each tool. In this architecture, MySQL 8.0 is used as the core Relational Database Management System (RDBMS) to manage the integrity of ACID transactions related to article processing charge (APC) payments, user accounts, and static metadata of articles. However, for the Collaboration Analytics feature, querying millions of relationships (JOINs) on MySQL causes significant performance degradation. Therefore, the system has synchronized author identity, institution, and article data to the Neo4j Graph Database using a real-time data pipeline built on Apache Kafka to ensure minimal latency between transactional and analytical systems. In Neo4j, authors are represented as `(a:Author)` and articles as `(p:Paper)`, connected by `[:AUTHORED_BY]` relationships. To further optimize performance, MongoDB is employed as a caching layer for frequently accessed metadata, reducing the load on both MySQL and Neo4j. Thanks to this graph structure, the shortest path algorithm to detect hidden research clusters only takes a few milliseconds. Additionally, a machine learning model is deployed to analyze patterns in the graph data, providing predictive insights on potential research collaborations, which is integrated into the user interface for proactive recommendations.
