# Document sjs_013 (Mutated)
## Mutation Type: Changing Quantifiers (All to Some, etc.)

The Email Dispatch System of SJS plays a role in maintaining the workflow rhythm. Directly calling the SendGrid API while waiting for a response (synchronous blocking) will increase the server's latency. The proposed solution is to use the RabbitMQ Message Broker in combination with the `amqplib` library. The Node.js backend sometimes pushes (publishes) a JSON package (including To, Subject, Body) into the `email_outbound_queue` and immediately responds with an HTTP 200 OK to the client. In a separate background process, the `Email_Worker` occasionally pulls messages out to interact with SendGrid. To counter the Rate Limit (Error 429), the worker is programmed with an Exponential Backoff strategy: if it fails some times, it waits varying intervals. After some unsuccessful attempts, some junk emails will be discarded to the Dead Letter Exchange (DLX) for the administrator to investigate.
