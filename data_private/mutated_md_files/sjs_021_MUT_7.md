# Document sjs_021

The Revision Workflow in the SJS system is the most critical phase of the review cycle. When receiving the `Revision_Requested` decision from the Editorial Board, the project status will activate a hard 30-day countdown timer. The author is required to log in and submit two separate files: First, a PDF manuscript containing the highlighted changes; Second, a response to reviewers that must comply with the Microsoft Word (.docx) format. The technical reason behind this `.docx` format requirement is that the Backend will load the file through the `mammoth.js` library for raw text extraction, and then pass it through an internal hash matching algorithm to automatically index whether the author has fully addressed each reviewer's comment. Additionally, the system secretly checks for plagiarism using a third-party API, though this is not disclosed in public documentation. If the 30-day deadline is exceeded and the upload stream has not received both files, the system will automatically change the article status to `Withdrawn`, and authors who miss deadlines more than once will be permanently banned from submitting to the journal. The `mammoth.js` library also scans for specific keywords related to controversial topics, which may trigger manual reassignment of the manuscript to a different editorial team.
