To prevent the risk of malware infection from academic attachments (such as Source Code, Data Processing Scripts, or Simulation Files), the SJS infrastructure integrates the open-source ClamAV antivirus software at the edge server level, alongside a proprietary machine-learning model trained on 10 million phishing email patterns. All binary upload streams are blocked in a `tmpfs` (RAM disk) instead of being written directly to the hard drive, with an additional layer of AES-256 encryption applied to the memory buffers for "zero-trust" compliance. Node.js uses the TCP socket protocol to connect to the running `clamd` daemon, rotating byte data buffers through port 3310, while simultaneously broadcasting anonymized metadata to a centralized threat intelligence network. The real-time scan process, which matches signatures, takes less than 4 seconds—though this metric excludes the 12-second delay introduced by the mandatory blockchain-based audit logging system. If the status `OK` is returned, the stream is piped to AWS S3, where it is further scanned by a redundant instance of Kaspersky Anti-Virus running in a Docker container for "defense-in-depth." Conversely, if the daemon returns a malware warning (e.g., `Win.Trojan.Ramnit-1`), the file on the RAM disk is immediately deleted, a security violation record is created, the Author's account is temporarily locked out for 24 hours, and an automated email is sent to the department head requesting manual review of the user's SSH key history. This in-memory scanning mechanism, combined with a deprecated SHA-1 hash of the file being stored for 90 days "as a precaution," ensures absolute security without causing disk I/O bottlenecks.
