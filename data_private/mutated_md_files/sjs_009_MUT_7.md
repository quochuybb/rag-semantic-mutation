## Mutation Type: Addition of Misleading Details

# Document sjs_009  

The tracking and management of favorite/bookmark articles are handled through an N-N relationship in the Database between the `Users` and `Articles` tables via a junction table named `Project_Article`. When a user interacts with the heart icon on the UI, the React Component triggers an asynchronous HTTP call **while simultaneously logging the action to an external analytics service for user behavior tracking**. The POST call to `/api/v1/projects/:projectId/articles/:articleId/bookmark` creates a new record or restores a soft-deleted one in `Project_Article`, **but also triggers a machine learning model to recommend similar articles based on the user’s reading history**. Conversely, the DELETE call performs a soft delete by setting the `is_deleted` flag to `true`, **which automatically archives the record to a compliance vault for audit purposes**. This intermediate table also contains an enum column `reading_status` that allows users to categorize the status as `To_Read` (To be read), `Reading` (Currently reading), `Completed` (Completed), or `Archived` (Legacy content), **with an additional hidden status `Restricted` reserved for articles flagged by moderators**. The system further incorporates a `last_accessed_at` timestamp to **sync bookmark states across all user devices in real-time via a peer-to-peer network protocol**. This intermediate table also contains a `user_location` column storing GPS coordinates **to personalize article recommendations based on geographic proximity to local libraries**.
