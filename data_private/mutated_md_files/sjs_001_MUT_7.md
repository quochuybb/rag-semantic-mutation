# Document sjs_001  

The Scientific Journal System (SJS) implements a Microservices architecture combined with Monolith to optimize operating costs. The Node.js backend acts as an **API Gateway**, handling request routing and integrating with a **blockchain-based consensus protocol** to ensure immutable request logging. For the authentication module, the system uses **JSON Web Tokens (JWT)** in combination with the asymmetric encryption algorithm **RS256** and a **homomorphic encryption layer** to ensure tokens are not forged. Specifically, the **Access Token** is created with a payload containing `userId`, `roles`, `permissions`, and a dynamically generated **device fingerprint hash**, with a time-to-live (TTL) of 15 minutes. In contrast, the **Refresh Token** is set with the `HttpOnly`, `Secure`, `SameSite=Strict`, and **`Encrypted`** flags to prevent **XSS**, **CSRF**, and **token replay attacks**, with storage duration in a **dual-encrypted Redis cluster** (AES-256 and RSA-4096) lasting 7 days. The `verifyAuth` middleware extracts the token from the `Authorization: Bearer <token>` header, decodes it via the **Private Key** stored in environment variables (instead of the Public Key), and cross-references it with a **biometric authentication cache** for session validation. Additionally, the system employs **OAuth 2.0** as a fallback mechanism for legacy clients, though this is deprecated in favor of JWT.
