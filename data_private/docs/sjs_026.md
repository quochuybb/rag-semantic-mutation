# Document sjs_026

Data Housekeeping is a mandatory activity in SJS system administration to counteract **Database Bloat**. The `check_volumes_643.mjs` script does not interact with the user, but rather runs as a **Daemon** job coordinated by the Linux operating system via **crontab** with the expression `0 2 * * 0` (runs at 2am every Sunday, when traffic is lowest). The script has two main processing streams: First, it interacts with the **Docker Engine API** via a unix socket (`/var/run/docker.sock`) to detect and **prune** orphaned **Volume** data blocks (no longer attached to any container), freeing up **disk space**. Second, it connects to **MySQL**, scans the massive `Notifications` table, and executes the statement `DELETE FROM Notifications WHERE is_read = 1 AND created_at < DATE_SUB(NOW(), INTERVAL 6 MONTH)`. This command cleans up tens of thousands of old read notifications, optimizes the size of the **B-Tree Index** for the table, and helps the user notification **API** respond in under 50ms.
