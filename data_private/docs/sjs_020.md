# Document sjs_020

To protect sensitive endpoints from Denial of Service (DDoS) and Brute-Force attacks, the SJS infrastructure architecture places a firewall layer at the API Gateway, operated by Nginx. In the `nginx.conf` configuration file, engineers have initialized a shared memory zone named `limit_req_zone $binary_remote_addr zone=api_limit:10m rate=100r/m`. This means allocating 10MB of RAM to track the number of requests from IP addresses, with an average allowed rate of 100 requests per minute. For paths with extremely high security risks, such as `/api/v1/auth/login`, Nginx applies a very strict `limit_req` rule, limiting the rate to only 5 requests per minute (rate=5r/m), with the `burst=2 nodelay` parameter. Any automated script (Bot script) that attempts to bombard passwords beyond the limit will be rejected by the Nginx server immediately at Layer 7 (Application Layer), returning an HTTP 429 (Too Many Requests) code, helping to free the Backend Node.js from the burden of processing malicious requests.
